# ナンバープレースWebアプリ 仕様書

## 0. 前提

- 本ドキュメントは `prompts/01_.md` の要求と、ラフ画像 `prompts/01_全体図.jpg` / `prompts/01_盤面マス.jpg`、および開発着手前のヒアリング結果をもとに作成した。
- 実装は `docs/roadmap.md` のフェーズ順に進める。技術的な指針は `CLAUDE.md` を参照。
- 本書中「(assumption)」と付記した項目は、ラフ画・元の要求に明記がなくチームでの合意により補った内容。実装時に変更したい場合は本書を更新すること。

## 1. 概要・対象ユーザー

PCブラウザで遊ぶナンバープレースWebアプリ。1人のユーザーがブラウザ上で盤面を選択・数字/メモを入力しながらパズルを解く。フェーズ1ではPC操作（マウス＋キーボード）のみを対象とする。

## 2. 画面構成

`prompts/01_全体図.jpg` のラフに基づく全体レイアウト：

```
+----------------------------+   +------+ +------+ +--------+
|                            |   | 戻る |  |消しゴム| |メモON/OFF|
|      9x9 盤面              |   +------+ +------+ +--------+
|   (CSS Gridで描画)         |
|                            |   +---+---+---+
|                            |   | 1 | 2 | 3 |
|                            |   +---+---+---+
|                            |   | 4 | 5 | 6 |
|                            |   +---+---+---+
|                            |   | 7 | 8 | 9 |
+----------------------------+   +---+---+---+

[  Check  ]                      [  New Game  ]
```

- 左: 9x9盤面。右: 操作アイコン3種（戻る／消しゴム／メモON/OFFトグル）と3x3配列の数字ボタン。
- 盤面の下にCheckボタン、数字パッドの下にNew Gameボタンを配置する。
- レイアウトはPC表示（横幅十分）を前提としたFlex/Grid構成とする。モバイル最適化は対象外（14章参照）。

## 3. 盤面仕様

- 盤面は9x9=81マスで、CSS Gridで描画する。3x3ブロックの境界線は他のマス境界より太くする。
- 盤面マスはクリックで選択される。選択できるのは1マスのみ（複数選択なし）。
- 選択中のマスは背景色を変える。加えて、その行・列・3x3ブロックに属するマスも（選択マスとは別の薄い色で）背景色を変える。
- 選択中マスに解答（value）が入力されている場合、盤面内で同じ数字が確定済みの全マス（候補メモは対象外）もハイライトする。選択中マスが未入力の場合はこのハイライトは行わない。選択マス自身はこのハイライトの対象に含めない。
- 確定マス（初期ヒントとして最初から数字が入っているマス）は編集不可（クリックで選択はできるが、数字入力・メモ入力・消去はできない）。ヒントであることが視覚的に分かるスタイル（太字＋淡い背景色など）で表示する。(assumption)
- ユーザーが入力した確定値のマスと、初期ヒントのマスは文字色などで区別する。(assumption)

## 4. セルの状態と表示

1マスは以下のいずれか1状態を持つ。

| 状態 | 表示 |
|---|---|
| 未入力 | 空欄 |
| 解答入力済み | 1つの数字を大きく中央表示 |
| メモ入力あり | 1〜9の数字を3x3ミニグリッド状に配置して表示（下記参照） |

解答（value）が入力されているマスはメモ表示を行わない。解答が消去された時点でメモ表示に戻る（メモ自体は解答入力中も内部的に保持してよいが、UI上は解答が優先表示される）。(assumption: 解答入力後にメモは保持するか消すかは実装簡易性を優先し「保持」を可とするが、少なくとも表示上は解答を優先する)

### 4.1 メモのデータモデル

1マスにつき、数字1〜9それぞれが独立して次の3状態のいずれかを持つ。

```ts
type MemoMark = 'none' | 'candidate' | 'notCandidate';

type Cell = {
  value: number | null;        // 確定解答。未入力はnull
  isGiven: boolean;             // 初期ヒントかどうか
  memos: Record<number, MemoMark>; // key: 1-9
};
```

- `candidate`（候補メモ）: 解答となりうる数字。3x3ミニグリッド内の対応位置に通常の数字として表示。
- `notCandidate`（非候補メモ）: 解答となりえない数字。3x3ミニグリッド内の対応位置に取り消し線付きの数字として表示。
- `none`: 何も表示しない。
- 1つの数字が `candidate` と `notCandidate` を同時に持つことはない（後述4.2の循環ロジックにより排他的に制御される）。
- ミニグリッド内の配置は数字の値に対応する（1=左上, 2=中央上, 3=右上, ... 9=右下）。`01_盤面マス.jpg` の表示例を参照。

### 4.2 メモ入力の循環ロジック

メモON/OFFトグルがON状態のとき、選択中マスに対して数字ボタン（画面の数字パッド、または物理キーボードの数字キー）で同じ数字を押すたびに、そのマスのその数字の `MemoMark` を次の順で循環させる。

```
none → candidate → notCandidate → none → ...
```

物理キーボードとオンスクリーンの数字パッドは全く同じ挙動をする。確定マス（isGiven）にはメモ入力できない。

## 5. 操作部

### 5.1 数字ボタン（1〜9、3x3配置）

- **メモOFF時**: 選択中マスにその数字を解答（value）として設定する。既に別の値が入っていれば上書きする。確定マスには入力不可。
- **メモON時**: 4.2 の循環ロジックに従い、選択中マスのその数字の `MemoMark` を切り替える。
- **入力済み数字の無効化（Issue #21）**: 盤面全体（確定マス・ユーザー入力どちらも含む）でその数字が解答（value）として9個配置済みの場合、その数字ボタンをグレーアウトし操作不可にする。正誤は問わない（誤答を含めて9個になった場合も無効化する）。物理キーボードの数字キー入力も同様に無視する。無効化中の数字を含むマスをCheckで誤答と判定し、ユーザーが消去または他の値に上書きすると、その数字の配置数が8以下に戻り自動的に再度入力可能になる。

  無効化の判定はメモON/OFFどちらのモードでも共通に適用する（メモ入力モード中でも、既に9個配置済みの数字については候補・非候補メモの切り替えも行えない）。

### 5.2 戻る（Undo）ボタン

- 直前の操作から遡って複数回連続で取り消せる、履歴スタック方式とする。
- 履歴に積むのは盤面に変化を与える操作（解答入力・解答消去・メモ変更・消しゴム）。マス選択やメモON/OFF切替は履歴に含めない。
- New Gameで新しい盤面を開始すると履歴はリセットされる。
- 履歴はブラウザリロードをまたいで保持する必要はない（永続化対象外。10章参照）。(assumption)

### 5.3 消しゴムボタン

- 選択中マスを未入力状態に戻す（value を null にし、全数字の memos を `none` にする）。
- 確定マス（isGiven）には無効（何も起きない、またはボタン自体を無効化）。(assumption: 無視する実装で可)
- この操作もUndo履歴に積まれる。

### 5.4 メモON/OFFトグルボタン

- メモ入力モードのON/OFFを切り替えるトグル。現在の状態が視覚的にわかるようにする（ラフ画のスイッチ意匠を参考に）。
- 選択中マスや盤面内容には影響しない。純粋に「次の数字ボタン入力の意味」を切り替えるモードスイッチ。

### 5.5 Checkボタン

- 8章「解答チェック機能」を実行する。

### 5.6 New Gameボタン

- New Gameボタン押下時、難易度選択モーダルを表示する（9章のクリア演出内の「New Gameへの導線」も同じモーダルを開く）。
  - 選択肢は7章の5段階（`easy`/`medium`/`hard`/`expert`/`master`）すべて。表示ラベルは英語のまま（`Easy`/`Medium`/`Hard`/`Expert`/`Master`）とする。
  - デフォルト選択は、直近に選択・保存された難易度（10章参照）。保存された難易度がない場合は `DEFAULT_DIFFICULTY`（7章）とする。
  - モーダルには難易度の選択肢と「決定」ボタン・「キャンセル」ボタンを配置する。「キャンセル」ボタンはモーダルを閉じるのみで盤面に影響しない。
- モーダルの「決定」ボタン押下時、進行中の盤面（1マス以上入力済み、かつ未クリア）がある場合は確認ダイアログ（例: `window.confirm` 相当）を出し、ユーザーが同意した場合のみ選択した難易度で新規開始する（同意しない場合はモーダルを開いたままにする）。進行中の盤面がない場合は確認ダイアログを出さず、選択した難易度で即座に新規開始する。
- 新規開始時、盤面・メモ・Undo履歴・チェック結果表示・難易度選択モーダルの開閉状態をすべてリセットし、選択した難易度を10章の永続化対象として保存する。

### 5.7 ヒントボタン

- ヒントボタン。押下ごとにハイライト→理由表示→再計算の順で循環する。詳細は15章参照。

## 6. キーボード操作仕様（PC対象）

| キー | 動作 |
|---|---|
| ↑↓←→ | 選択マスを1つ移動。盤面端では移動しない（ラップしない） |
| 1〜9 | 数字パッドの同番号ボタンと同じ挙動（メモON/OFF状態に従う） |
| Delete / Backspace | 消しゴムボタンと同じ挙動 |

- クリックによるマス選択と矢印キーによる移動は独立して機能し、常に最新の選択マスに対して数字キー入力・削除が反映される。

## 7. 難易度・盤面生成

- New Gameボタン押下時に表示されるモーダル（5.6章）で難易度を選択できる。選択肢は `easy` / `medium` / `hard` / `expert` / `master` の5段階で、`numberPlaceService.ts` が `DIFFICULTIES`（この順序の配列）として公開する（12章参照）。UIコンポーネントはこの一覧をハードコードしない。
- 既定難易度の定数 `DEFAULT_DIFFICULTY` は `numberPlaceService.ts` 内で定義し、値は `medium` とする。初回起動時（永続化された難易度がない場合）のモーダル初期選択に用いる。

## 8. 解答チェック機能

- Checkボタン押下時、盤面上の「ユーザー入力済みの解答マス（isGiven=falseかつvalue≠null）」について、正解（生成時に保持している解の盤面）と一致するかを判定する。
- 不一致のマスにのみエラー色を付ける。一致しているマス・未入力マス・確定マス（ヒント）には何もしない。
- エラー色が付いたマスは、そのマスの入力（value）を変更した時点でエラー表示を解除する（メモの変更やCheckの再実行では解除されない。あくまで該当マスの value 変更が解除条件）。
- 入力中のリアルタイム矛盾検知（重複数字のハイライト等）は行わない。矛盾判定はCheckボタン押下時のみ。

## 9. ゲームクリア機能

- 全81マスが入力済みかつ、すべて正解と一致した時点で自動的にクリアと判定する（ユーザーがCheckボタンを押さなくても、値が確定するたびに内部的に判定してよい）。
- クリアを検出したら、クリア演出（モーダルダイアログ等）を表示する。演出には「クリアした旨のメッセージ」と「New Gameへの導線」を含める。(assumption: 経過時間・手数などのスコア表示は行わない。13章参照)

## 10. 状態永続化（localStorage）

- ブラウザをリロードしても進行中の盤面（各マスのvalue・isGiven・memos、選択マス、メモON/OFF状態、初期盤面・正解盤面、選択中の難易度）を復元できるよう、変更の都度 `localStorage` に自動保存する。
- 保存キー・スキーマ例（実装時に確定してよい設計方針）:
  - キー名: `numberplace:v2:gameState` のようにスキーマバージョンを含める。将来データ構造を変更した場合はバージョンを上げ、旧データは破棄して新規ゲームにフォールバックする（難易度フィールドの追加に伴い `v1` から `v2` へ上げた）。
  - 保存内容: 初期盤面（givenの位置と値）、正解盤面、現在の各セルのvalue/memos、選択中マス、メモON/OFF状態、クリア済みフラグ、現在の盤面の難易度（New Gameモーダルの次回デフォルト選択に使う）。
  - Undo履歴・New Gameモーダルの開閉状態・ヒント状態は保存対象外（10.1参照、5.2・5.6・5.7とも整合）。
- 保存されたデータが壊れている／スキーマバージョンが不一致の場合は、新規ゲーム相当の初期状態にフォールバックする（エラーで落とさない）。

## 11. データモデル（型定義の指針）

```ts
type Difficulty = 'easy' | 'medium' | 'hard' | 'expert' | 'master';

type MemoMark = 'none' | 'candidate' | 'notCandidate';

type Cell = {
  value: number | null;
  isGiven: boolean;
  memos: Record<number, MemoMark>; // 1-9
};

type Board = Cell[][]; // 9x9

type Position = { row: number; col: number }; // 0-8

type GameState = {
  board: Board;
  solution: number[][];      // 9x9の正解値
  selected: Position | null;
  isMemoMode: boolean;
  isCleared: boolean;
  errorCells: Position[];    // Checkボタンで検出された誤答マス
};

type HistoryEntry = {
  // undo用のスナップショット、もしくは差分。実装時にどちらかを選択してよい
  board: Board;
};
```

## 12. numberPlaceService.ts インターフェース仕様

UI層（Reactコンポーネント／カスタムフック）は、パズルの生成・解答・判定ロジックについて **`src/services/numberPlaceService.ts` が公開する関数・型のみ** に依存する。外部ライブラリ（フェーズ1: sudoku-core等）や自作アルゴリズム（フェーズ3）の型・実装をUI層から直接importしてはならない。これはフェーズ3での差し替えをUIに一切影響を与えずに行うための必須境界である（`CLAUDE.md` にも明記）。

想定インターフェース（最終的な関数名・シグネチャは実装時にサービス内で確定してよいが、UIから見た「契約」としてこの形を維持すること）:

```ts
// src/services/numberPlaceService.ts が公開する契約の例
export type Difficulty = 'easy' | 'medium' | 'hard' | 'expert' | 'master';

export type PuzzleBoard = {
  given: (number | null)[][];    // 9x9、初期ヒント（ヒントでないマスはnull）
  solution: number[][];          // 9x9、完全な正解
};

export const DIFFICULTIES: readonly Difficulty[]; // 5段階、選択UIの表示順

export function generatePuzzle(difficulty: Difficulty): PuzzleBoard;

export function isBoardComplete(userValues: (number | null)[][]): boolean;

export function checkAnswers(
  userValues: (number | null)[][],
  solution: number[][]
): boolean[][]; // trueなら誤り

export type HintTechnique = 'nakedSingle' | 'hiddenSingle';

export type Hint = {
  position: { row: number; col: number };
  value: number;
  technique: HintTechnique;
  techniqueLabel: string; // 例: "単一候補（Naked Single）"
  reasonText: string;     // 例: "このマスは候補が5の1つだけに絞られます"
};

export function findHint(
  userValues: (number | null)[][],
  solution: number[][]
): Hint | null;
```

- フェーズ1: 内部実装は npm ライブラリ（想定: `sudoku-core`）呼び出しをラップする。
- フェーズ3: 内部実装をバックトラッキング法による自作アルゴリズムに差し替える。上記の公開関数シグネチャ・戻り値の意味は変更しない。フェーズ1で書いたテスト（`numberPlaceService` に対するユニットテスト）がフェーズ3移行後も無修正で通ることを完了条件とする。

## 13. 配色・スタイルガイド（Tailwind想定・指針）

以下は目安であり、実装時にTailwindのデザイントークンとして具体化してよい。

| 要素 | 色の方向性 |
|---|---|
| 選択中マス | はっきりした強調色（例: blue系の濃いめの背景） |
| 選択マスと同じ行・列・ブロック | 選択色より薄い同系色の背景 |
| 選択マスと同じ数字を持つマス | 選択色・関連マス色とは異なる系統の背景（例: amber系）。優先順位は 誤答 > 選択中 > 同じ数字 > 関連マス の順で、重なった場合は優先度の高い表示を採用する |
| 確定マス（ヒント）の文字 | 濃いグレー・太字、薄いグレー背景で解答済みマスと区別 |
| 入力済み（9個）の数字ボタン（Issue #21） | グレーアウト（薄い文字色・背景色）＋操作不可（`disabled`）で、他の数字ボタンと明確に区別する |
| ユーザー入力の解答文字 | 通常色（例: 青系や黒） |
| 誤答（Check後） | 赤系の背景または文字色 |
| 候補メモ | 小さいグレー文字 |
| 非候補メモ | 小さいグレー文字＋取り消し線 |
| ヒント対象マス（Issue #22） | 背景色の優先順位とは独立して、目立つ枠線で常に強調表示する |

## 15. ヒント機能（Issue #22）

- プレイヤーが次にどこを見ればよいか分からなくなった際に、注目すべきマスと使うべき解法を示して支援する機能。解答（value）を自動入力することはせず、あくまで「このマスに注目すべき」「候補をこう絞れる」という示唆に留め、実際の入力はユーザーに行わせる。
- 対応技法は次の2つに限定する（ポインティングペア・X-Wing等のより高度な技法は対象外。将来必要になれば別Issueで拡張する）。
  - **単一候補（Naked Single）**: 対象マスの候補が1つだけに絞られる。
  - **◯◯内消去（Hidden Single）**: 対象マスの候補は複数残るが、同じ行・列・3x3ブロックのいずれかの中でその値が入りうるマスが対象マスだけになっている。
- ヒントボタン（5.7章）押下ごとに、以下の状態を循環する。
  1. **ハイライト**: `findHint`（12章）で技法を再計算し、対象マスを盤面上でハイライト表示する（技法名・理由はまだ出さない）。対象マスは自動的に選択状態にもなる（数字の入力はユーザー自身が行う）。
  2. **理由表示**: 続けてヒントボタンを押すと、直前に計算した対象マスはそのままに、技法名（例:「単一候補（Naked Single）」）と理由文（例:「このマスは候補が5の1つだけに絞られます」）を表示する。
  3. 理由表示の状態から更にヒントボタンを押すと、新しいヒントを再計算し、1に戻る。
- 該当する技法のマスが盤面上に1つも見つからない場合（`findHint` が `null` を返す場合）は「ヒントが見つかりませんでした」という旨のメッセージのみを表示し、盤面のハイライトは行わない。
- 盤面に変化を与える操作（解答入力・消しゴム・メモ変更・Undo）が発生した場合、およびNew Gameで新しい盤面を開始した場合、ヒントの状態は破棄され初期状態（何も表示しない）に戻る。
- ヒントの利用回数に制限やペナルティは設けない（無制限に利用できる）。
- ヒントの状態はUndo履歴・New Gameモーダルの開閉状態と同様にブラウザリロードをまたいで保持する必要はない（永続化対象外。10章参照）。
